# 定时发布改「立即上架 / 修改定时时间」调研记录

> 调研日期：2026-09-10 ｜ 调研范围：华为 / 荣耀 / vivo / OPPO / 小米 五家安卓应用商店开放平台
> 场景：应用设置了**定时发布**，已**通过审核**但未到定时上架时间，此时想：
> ① 立即上架（跳过定时等待）；② 或修改原定时时间。

---

## 一、结论总览

| 平台 | 审核后改立即上架 | 审核后改定时时间 | 结论 |
|------|:---:|:---:|------|
| **华为** | ✅ 有 API | ✅ 有 API | 唯一官方完整支持（on-shelf-time） |
| **荣耀** | ❌ 常规定时无 | ❌ 常规定时无 | 仅「分阶段发布」模式有 API（update-phased-release-info） |
| **vivo** | ❌ 常规定时无 | ❌ 常规定时无 | 仅「分阶段发布」模式有 API（可改开始时间） |
| **OPPO** | ❌ 无 | ❌ 无 | API 完全无此能力；控制台分阶段仅可改未生效阶段的时间 |
| **小米** | ❌ 无 | ❌ 无 | API 仅 3 个接口；控制台分阶段可转全网但无 API |

**一句话**：常规定时发布提交后想反悔，只有华为给了官方 API；荣耀/vivo 需改用「分阶段发布」提交方式绕行；OPPO/小米只能登控制台手动操作。

---

## 二、各平台详情

### 1. 华为 AppGallery Connect ✅

**接口**：`PUT /api/publish/v2/on-shelf-time?appId={appId}`

| 参数 | 说明 |
|------|------|
| changeType | **2 = 定时上架改为审核通过后立即上架**；**3 = 变更定时上架时间**（此时 releaseTime 生效） |
| releaseTime | 定时上架时间（yyyy-MM-ddTHH:mm:ss+0800），文档注明 changeType=3 时有效；changeType=2 时传当前时间占位即可 |
| releaseType | 1 = 全网发布（当前文档仅支持 1） |

- 另有 `PUT /api/publish/v2/phased-release`：管理分阶段发布（分阶段转全网等）。
- 文档：developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/agcapi-update-releasetime-0000001158365053
- **已在本仓库实现**：`HuaweiAdapter.release_now()`（changeType=2）；Web 看板 `POST /api/release-now`；前端华为「待发布」状态卡「立即上线」按钮。
- 限制：Harmony 应用不支持该 API（提示走 AGC 控制台）。

### 2. 荣耀应用市场 ❌（常规定时）

- `submit-audit` 的 releaseType：1=审核通过后立即发布 / 2=指定时间发布 / 3=分阶段发布。**releaseType=2 提交后即定型，无修改接口**。
- 仅 releaseType=3（分阶段发布）有 `update-phased-release-info`：
  - operationType=4：提前全网发布（无需重新审核）；
  - operationType=1：修改 releaseStartDate（仅「待发布」状态可改）。
- 文档：本地 `docs/honor_api_guide.txt`（update-phased-release-info 章节，约 4375 行）。

### 3. vivo 应用商店 ❌（常规定时）

- 常规更新 `app.sync.update.app`：onlineType/scheOnlineTime 提交时定型；待上架状态下再调用报 **错误码 12021「当前更新应用待上架，不允许更新」**（已实测）。
- 仅分阶段发布有修改能力（均要求当前为分阶段「待发布」状态）：
  - `app.sync.create.update.stage.app`（doc/882，文件上传方式）；
  - `app.create.update.stage.app`（doc/883，下载文件方式）；
  - 可更新 stagedStartTime，**不能小于当前时间**（错误码 29003）→ 设为 10 秒后即等效「提前上线」；
  - `app.query.stage.details`（doc/884）查分阶段详情。
- 控制台：分阶段发布页可手动转全网。

### 4. OPPO 软件商店 ❌

- API 能力仅覆盖传包接口族（wiki doc_id 10997 树）：10999 发布版本 app/upd、11000 更新资料、11003 文件上传、11004/11005 查询、11001 任务状态。
- app/upd 的 online_type/sche_online_time 提交时定型；审核通过后再调 app/upd 直接报错（已实测）。
- 控制台「分阶段发布」（doc 11546）：仅可修改**未到生效时间**阶段的时间，且填写要求与创建时相同（阶段一起始 ≥ 当前+24h）；无手动转全网、无 API。

### 5. 小米应用商店 ❌

- devupload API 仅 3 个：dev/push（提交）、dev/query（查询）、dev/category（分类）。onlineTime 提交时定型。
- 控制台「分阶段发布」（dev.mi.com 文档 pId=1364）：可更新阶段设置、**转全网（无需重新审核）**、暂停/恢复/取消分阶段；但**起始时间不可改**，且全部仅网页操作，无 API。

## 三、变通路线对比（针对荣耀/vivo/小米/OPPO 的诉求）

| 路线 | 说明 | 代价 |
|------|------|------|
| 华为式直连 | on-shelf-time 一个接口搞定 | 仅华为支持 |
| 分阶段发布提交 | 荣耀/vivo/小米控制台或 API 可「转全网/提前结束分阶段」，无需重审 | 必须一开始就用分阶段方式提交，不能事后从常规定时切换 |
| 重新提交 | 撤回审核 → 重新提交为立即发布 | 需重新走审核，慢 |

> 注：分阶段发布本身有「按比例逐步放量」的发布语义，若只想要「可控的上线时间」，把阶段一比例设为 100% 即近似定时发布，且保留了「随时提前」的灵活性。

## 五、本仓库落地情况

- `app_store/base.py`：`StoreAdapter.release_now()` 默认抛「官方未提供接口」；
- `app_store/stores/huawei.py`：华为实现（on-shelf-time，changeType=2）；
- `app_store/web.py`：`POST /api/release-now`（app_id + platform）；
- 前端：华为「待发布」状态卡「立即上线」按钮（确认弹窗 → 执行 → 刷新）；
- 平台能力表：README「审核后立即上线」列（仅华为 ✅）；
- 客服反馈：`docs/开放平台API能力需求-已上架版本号.md` 需求二章节（gitignored，含对四家的具体诉求）。
- **待验证**：华为真实「待发布」版本的端到端实测（需实际存在定时待上架版本时触发）。

## 六、给各平台的诉求建议（可发客服/商务）

1. 参照华为 `on-shelf-time`，提供「定时发布 → 立即上架」切换接口；
2. 或至少允许修改未生效的定时上架时间（当前时间之后 N 秒即等效立即上架）；
3. 分阶段发布的「提前转全网/修改开始时间」能力开放 API（荣耀/vivo 部分已有，补齐 OPPO/小米）。
